# ムシヨケ・ナビ UI/UX改善・実装仕様書

版: 1.0 / 2026-11-06

## 0. 目的・制約・現状

**目的**：虫が苦手な利用者が、外出直前にスマホ片手で、比較的虫に出会いにくい徒歩ルートを選べるようにする。

**制約**：HTML/CSS/JavaScript 1ファイル、Leaflet＋OpenStreetMap、日本語、375px最優先、PC対応、ライト・ダーク対応、写真・イラスト・アイコン・絵文字を含む虫の視覚表現禁止。外部画像素材の新規追加なし（OSM地図タイルは例外）。現行の経路・リスク・Gemini接続は既存実装があれば優先し、UI改修で壊さない。

**引継ぎ上の重要な前提**：本パッケージはスクリーンショットから新規実装したプロトタイプ。元の既存コード、Cloudflare Workerエンドポイント、Gemini認証設定は受領していない。したがって、既存環境と同一のアルゴリズムや接続が再現されたとは主張しない。`index.html` の `CONFIG` と adapter 関数を元の実装に統合すること。

## 1. 現行画面の問題点（重要度）

| 重要度 | 問題 | 利用者の懸念 |
|---|---|---|
| 高 | PC前提の2カラム | スマホで地図と結果を同時に追いにくい |
| 高 | 入力・操作のタップ領域が小さい | 歩く直前に押し間違える |
| 高 | 条件・天気・ルート・AIが同時表示 | まず行き先だけ入れたい |
| 高 | リスク数値だけでは意味不明 | 4と9の違いがわからない |
| 高 | ルートカードと地図の対応が弱い | どの線を選んだかわからない |
| 中 | AI文章が小さな領域にある | 説明を読めない |
| 中 | 安心感より警告が先に立つ | 不安を増幅する |
| 中 | 絞り込み条件が画面を占有 | 普段使わない項目に目がいく |
| 中 | 主要ボタンの優先度が不明 | 次に押す場所を迷う |
| 低 | 地図が複雑に見える | 必要な道を識別しにくい |

## 2. 参考UIパターン

- Google マップ：地図全面＋下部可変シート、地図上の線と候補の連動。
- Yahoo!乗換案内：比較軸を短いラベルで明示。虫リスクは「リスク低め／少し注意／注意が必要」。
- NAVITIME：大きな所要時間を主要な判断情報にする。
- Citymapper：複数候補を同じフォーマットのカードで比較する。

競合のロゴや画像は使用しない。

## 4. デザイン仕様

### 4.1 色（CSS変数）

| 用途 | ライト | ダーク |
|---|---|---|
| 背景 | `#F5F7F6` | `#101A18` |
| カード | `#FFFFFF` | `#1B2925` |
| 主要文字 | `#20332F` | `#F0F5F2` |
| 補助文字 | `#61736E` | `#B2C1BB` |
| アクセント | `#0C7568` | `#59C5B0` |
| 低リスク | `#16806B` | `#69D3B0` |
| 中リスク | `#A97708` | `#E8BD5B` |
| 高リスク | `#B9433D` | `#F08078` |

リスク区分の**暫定UI閾値**：0〜24＝リスク低め、25〜59＝少し注意、60〜100＝注意が必要。既存で正式区分がある場合は優先する。数値は確率ではない。

### 4.2 フォント

- 和文：`Noto Sans JP`、数字：`Inter`。
- アプリ名：18px/700、見出し：16px/700、カードタイトル：15px/600、本文：14px/400、入力：16px/500、主要所要時間：25〜26px/700、リスク値：22〜23px/700、注記：12px/400。
- 本文行間1.6、数字はtabular-nums。

### 4.3 レイアウトとコンポーネント

- 左右余白16px、内部余白16px、要素間8〜12px、セクション間20px。
- 入力欄52px高・12px角丸、主ボタン52px高・14px角丸、チップ最低42px高、タップ領域44px推奨。
- ルートカード16px角丸、通常枠線1px、選択中2pxアクセント。選択中は112px以上、その他76px以上。
- ボトムシート：上側角丸24px、閉状態112px+safe-area、中段44dvh、展開82dvh。内部スクロールを優先する。
- モバイル：背景地図＋上部検索欄＋シート。幅768px以上：右幅400pxの入力＋結果パネル、左が地図。
- iPhone Safe Area：`env(safe-area-inset-bottom)`、高さは`100dvh`。地図再計算は`map.invalidateSize()`。
- 検索中はボタンを無効化し、UIが固まったように見せない。AI失敗は再試行を提供。
- ダーク時にOSMの地図タイルをCSS反転しない。

### 4.4 ルート描画・カード

- ルートカードに所要時間、距離、リスク数値、区分名、A〜Cの候補名、選択状態を表示。
- 選択ルート線は7px／不透明度1.0、非選択は4px／0.5。白色等の輪郭を追加して地図に埋没しないようにする。
- カードとPolylineを双方向に連動。線の透明当たり判定は幅20px程度。
- 区間別スコアがない場合、区間ごとに違う色を表示しない。ルート全体を同じ色とする。
- 経路を変更する際、地図範囲は`fitBounds`、シートで隠れないパディングを考慮。

### 4.5 条件とAI

- 条件は「条件を変更」にまとめ、虫の選択：蚊、ゴキブリ、羽虫、ハエ。テキストのみ使用。
- 気象条件は「今の天気」「真夏の夕方（デモ）」「手動設定」。手動は気温・湿度・時間帯。
- AIはサーバー側のGemini API連携で回答させる。鍵をHTML/クライアントJSに記載しない。AIの成功表示をハードコードしない。
- 文言「虫が絶対出ない」禁止。「比較的リスクが低い」と記述。

## 5. 実装順序（効果大・作業小の順）

1. CSS変数／フォント／余白／ボタンの統一。
2. リスク区分ラベルとカード形式の統一。
3. モバイルの全面地図＋ボトムシート化。
4. 地図の線とカードの双方向選択。
5. 条件の折りたたみ・AI回答の読みやすいシート表示。

## 6. ブランド・言葉づかい

ブランドコピー「歩く道に、少しの安心を。」。自然・落ち着き・判断しやすさを重視。虫を怖がらせる写真や記号は絶対に使わない。「危険度」より「リスク」、「大量発生」より「リスクが高めと推定」、「絶対に安全」より「比較的リスクが低い」を優先。スコアは推定であり遭遇確率ではない旨を表示する。

## 7. 本ZIPの実装と既存環境との差分

- `index.html` は1ファイルのレスポンシブUI。外部取得はLeaflet CSS/JS、Google Fonts、OSMタイル、公開地理API。
- 地名→緯度経度：Nominatim公開API（試作）。
- ルート取得：OSRM公開デモAPI（試作）。**公開OSRMの `/foot` 表記は必ずしも歩行者専用ルーティングを保証しない**。本番は既存の歩行者対応ルートAPIに戻すこと。代替経路が3本未満になる場合もある。
- 気象：Open-Meteoの現況（試作）。取得できない時は暫定条件にフォールバックして明示。
- 周辺施設：Overpass公開APIの公園、水路、飲食店、コンビニを取得（試作・取得失敗あり）。経路周辺の厳密な空間演算ではなく近接サンプリングを使用。
- リスク：試作用のヒューリスティック。**現行アプリと同じ点数を再現しない**。推論・予測の妥当性は未検証。本番では元のリスク計算エンジンへ置換する。
- Gemini：既存APIと認証が未提供のため、未接続。`CONFIG.aiEndpoint` をCloudflare Workerなどの保護されたサーバー側エンドポイントに指定する。APIキーは配布ファイルに埋め込まない。
- 既存バックエンドの経路APIを使う場合は`CONFIG.routeEndpoint`を指定。レスポンス形式は下記。

### 7.1 routeEndpoint の契約

POST JSON:

```json
{"start":{"lat":35.6812,"lng":139.7671,"label":"東京駅"},"end":{"lat":35.6735,"lng":139.7596,"label":"日比谷公園"}}
```

返却 JSON:

```json
{"routes":[{"coordinates":[[35.6812,139.7671],[35.6735,139.7596]],"distance":1500,"duration":1080}]}
```

`coordinates` は `[緯度,経度]` のリスト、距離はメートル、時間は秒。最大3件。エラーは非2xx。

### 7.2 aiEndpoint の契約

POST JSON（例）:

```json
{"start":{"lat":35.6812,"lng":139.7671,"label":"東京駅"},"end":{"lat":35.6735,"lng":139.7596,"label":"日比谷公園"},"weather":{"temperature":21,"humidity":61,"time":"day","source":"open-meteo"},"avoidedInsects":["ゴキブリ"],"routes":[{"id":"A","durationSeconds":1080,"distanceMeters":1500,"risk":12}]}
```

成功 JSON:

```json
{"recommendation":"A","text":"ルートAがおすすめです。..."}
```

Gemini APIキーはWorkerシークレットに保存。入力はサーバーで検証し、レート制限、タイムアウト、CORS制御を実装。エラーは意味のあるHTTPステータスで返す。

## 8. 品質保証・受け入れ基準

- 375×812pxで横スクロールがない。
- 地名検索、現在地、地図タップの3つの場所選択が動作する。
- 0〜3件のルートを扱え、カードと線が同期する。
- 条件切り替えで既存の経路座標を失わず、リスクが再評価される。
- AI推論のローディング、成功、失敗（再試行）がある。
- ライト・ダーク、375px・768px以上で確認。
- 虫の視覚表現が一切ない。リスクは推定であることを明示。
- 既存アプリへの統合では、もとの経路検索・リスク計算・AIが退行しない。

## 9. Claudeへの最終依頼

このZIPの `index.html` をUIベースとして使用し、**既存のCloudflare WorkerとGitHubの元コード**に統合してください。既存のソースコード、エンドポイント、認証方式、リスク式を確認してから、上記adapterを差し替えてください。デモ用OSRM・リスク式を本番に残さないでください。日本全国の任意2地点に対応し、ハードコードした経路や結果は用いず、実際にブラウザで検証してください。GitHubへのコミット／Cloudflareへのデプロイはアクセス権を確認してから実行してください。
